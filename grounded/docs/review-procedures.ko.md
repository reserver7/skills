# 검토 절차 보존

[English](review-procedures.md) | **한국어**

통합은 선택형 단계를 제공하되 선택된 전체 검토 절차를 짧은 체크리스트로 조용히 대체하지 않습니다. 관련 없는 작업에 비용을 부과하지 않도록 세부 자료는 해당 단계에서 불러옵니다.

| 절차 | 유지하는 검사와 산출물 | 통합 조정 |
|---|---|---|
| CEO 감사 | 시스템 근거, 회고, UI 탐지, 확장 영역 | 기존 OpenSpec·대화 입력 사용. 별도 피치나 디자인 인계 요구 없음 |
| CEO 범위 도전 | 전제, 기존 코드 재사용, 이상적 상태, 대안 2~3개, 접근 승인, 시간 관점 확인, 네 가지 범위 모드 | 자동 요구사항 작성 스킬 없음. 기존 원본 문서에서 편집 |
| CEO 11개 섹션 | 아키텍처, 오류·복구, 보안, 데이터 흐름, 품질, 테스트, 성능, 관측성, 배포, 장기 운영, 조건부 UX | 상세 섹션과 다이어그램 보존. 사용자 승인에 따른 진행 속도·위임 준수 |
| CEO 판정 | 확인된 APPROVE/REVISE/REJECT, 범위 고정, 근거, 후보, 기록 | 호스트 중립 검토 경로. ENG 자동 실행 없음 |
| 엔지니어링 검토 접수 | 단독/CEO 검토 후 접수, 범위 확인, 늦은 변경, 이전 차단 판정 | 승인된 사실은 그대로 재사용. 오래된 기록은 승인을 뜻하지 않음 |
| 엔지니어링 4개 섹션 | 아키텍처 다이어그램, 품질 근거, 완전한 테스트 범위·목표, 성능 차이 | 기술 세부와 차이를 유지. 범위 인터뷰나 구현 코드 리뷰를 반복하지 않음 |
| 병렬화 | 기존 작업 의존성 표, 모듈 충돌, 작업 레인과 순서, 명시적 생략 조건 | 분석만 수행. worktree/에이전트 시작이나 두 번째 작업 목록을 자동 생성하지 않음 |
| 엔지니어링 판정 | ADR 후보, 확인된 판정, 완전한 검토 기록, 인계 권고 | 구현은 OpenSpec 작업과 선택된 Superpowers/Ponytail 스킬에서 진행 |
| ADR 접수·인터뷰 | 신규/갱신/폐기만, 범위·연결 확인, 여섯 인터뷰 분기 | 피치 의존성 대신 요구사항·근거 참조 사용. SDD는 선택 사항 |
| ADR 반대 관점 검토 | 신규 엔지니어, 유지 관리자, 제품 책임자 관점. 공통 발견은 승격해 한 번 수정 | 근거를 요구하며 할당량을 채우려고 발견 사항을 만들지 않음 |
| ADR 관문·이력 | 여섯 기준 중 다섯 통과, 미해결 자리표시자 없음, 모놀리스 방지 단계, 필수 섹션·참조·후속 대체 | 외부 프로필 대신 내장 기본값 사용. 정확도 백분율을 주장하지 않음 |

구식 설정/로케일 카탈로그, 자동 단계 연쇄, 중복 PRD/계획, 별도 메모리 서비스 의무화, 사용할 수 없는 호스트별 도구 이름은 의도적으로 제외했습니다. 그렇다고 실질적인 검토를 생략해도 된다는 뜻은 아닙니다.

원래 관문의 수치 절차는 보존했지만 과거의 “90%” 표기를 정확도 90%로 해석하지 않습니다. ADR 모놀리스 방지 임계값은 L1(대안 6개 초과 또는 결과 12개 초과), L2(8개 초과 또는 18개 초과), L3(12개 초과 또는 30개 초과)이며 각각 안내, 명시적 확인, 거부를 적용합니다.

이 문서는 절차 대응표이며 실제 실행 품질의 벤치마크가 아닙니다. 결함 탐지 동등성이나 토큰 절감 효과를 주장하기 전에 필요한 근거는 [검증 계획](validation.md)을 참고하세요.

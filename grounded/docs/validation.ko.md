# 검증 기록 요약

[English 원문](validation.md) | **한국어**

이 문서는 상세 검증 기록의 한국어 요약입니다. 정확한 실행 환경, 시나리오 표, 관찰 내용과 토큰 수는 [영문 원문](validation.md)을 기준으로 확인하세요.

## 현재 결론

이 환경에서 전체 에이전트 품질 벤치마크나 새 컴퓨터에서의 설치 통합 검증은 수행하지 않았습니다. 제한된 런타임 스모크와 정적 검사는 전체 품질 동등성이나 토큰 절감 효과를 입증하지 않습니다. 호스트·모델·세션 문맥이 포함된 토큰 수는 Grounded에만 귀속할 수 없습니다.

## 공개 전 필요한 검증

문서의 체크리스트에 따라 Codex와 Claude Code를 각각 평가해야 합니다. 같은 호스트 내에서 동일한 픽스처·요청·모델·추론 수준을 사용하고 다음을 확인합니다.

1. 깨끗한 macOS/Linux 환경에서 두 번 설치해 결과가 안정적이고 호스트마다 중복 스킬이 없는지 확인합니다.
2. 기존 사용자 지침을 보존하고 백업, 편집된 관리 파일 거부, 충돌 감지, 배포 실패 시 롤백을 임시 환경에서 확인합니다.
3. 오타/스타일 수정에는 SDD, Jev, 선택 검토, 에이전트, worktree 절차가 개입하지 않는지 봅니다.
4. 국소 버그는 디버깅, 범위가 맞는 회귀 확인, 완료 검증을 거치고 중복 계획을 만들지 않는지 확인합니다.
5. OpenSpec 기능은 제안서/설계/작업 하나를 사용하고, 구현이 그 작업을 따르며 기본 코드 리뷰와 적절한 수용 검사가 있는지 봅니다.
6. 검토, ADR, Jev는 요청된 경우에만 동작하고 자동으로 다음 단계를 연쇄하지 않는지 확인합니다.

호스트별 결과를 각각 기록하고 토크나이저가 다른 모델 간 토큰 수를 효율성 점수로 비교하지 않습니다. 전체 기준과 남은 시나리오는 [영문 검증 기록](validation.md)을 참고하세요.

CI 사례는 Context7 `resolve`→`query`와 CI 전문을 호출해 캐시 의존성 파일 누락을 찾았습니다. 테스트 실행 금지 사례는 디버깅·완료 검증만 적용하고 TDD나 테스트 실행은 건너뛰었습니다. side-effect/dedup 사례는 재시도·만료 시점 회수·완료 키 중복 방지·동시 호출 단일 승자를 테스트해 독립 재실행 4/4가 통과했습니다. SDK 사례도 Context7을 호출했지만 정확한 1.0.0 문서는 색인되지 않아 v1.x 문서를 근거로 정확 버전 동작을 단정하지 않았습니다. 정확한 upstream 1.0.0 근거는 확인하지 못해 호환성 판단은 부분 결과로 기록했습니다. 네 세션 입력은 983,404(캐시 876,800), 출력 5,775 토큰이며 전체 세션 수치입니다. 이 묶음에서는 추가 규칙 변경을 하지 않았습니다. [상세 비교](validation.md)
- **SDK 1.0.0 공식 원문 후속:** Context7에서 v1.x 문서만 확인된 뒤 공식 npm 메타데이터와 1.0.0 배포 tarball을 메모리에서 읽었습니다. 패키지 export map은 `dist/*`를 가리키고, tarball에는 저수준 `Server` 클래스가 있지만 `dist/server/mcp.js` 및 `McpServer` 심볼은 없습니다. 따라서 해당 픽스처의 `McpServer` import가 정확한 1.0.0 버전에서 지원되지 않는다는 점을 확인했습니다. 이는 이전의 “정확 버전 근거 미확인”을 대체하는 결과입니다. 검증 에이전트는 Context7 결과가 v1.x뿐임을 밝혔지만 공식 fallback 조회는 수행하지 않아 그 단계는 여전히 누락했습니다. [공식 npm 1.0.0 메타데이터](https://registry.npmjs.org/%40modelcontextprotocol%2fsdk/1.0.0), [현재 공식 v1 서버 가이드](https://ts.sdk.modelcontextprotocol.io/server)
- **정확 버전 fallback 실행 재검증:** 강화된 규칙으로 MCP SDK 1.0.0 읽기 전용 픽스처를 Luna Medium에서 다시 실행했습니다. 고정 버전과 소스를 확인하고 Context7 `resolve-library-id`→`query-docs`를 호출했으며, v1 문서로 1.0.0 동작을 입증할 수 없다고 정확히 밝혔습니다. 그러나 공식 릴리스/태그 원문이나 패키지 배포물을 확인하지 않고 중단했습니다. 이벤트에도 공식 원문을 가져오려는 명령이 없습니다. 결과 답변은 이후 v1 문서를 import/API 계열의 근거로 인용한 뒤 정확한 signature는 미검증이라고 덧붙였습니다. **fallback 실행은 실패, 불확실성 공개와 무변경 경계는 통과**입니다. 원문에 접근할 수 없었다는 증거는 아닙니다. 이번 실행은 가져오기를 시도하지 않았습니다. 이에 따라 정책과 한영 워크플로에서 정확한 태그/릴리스 원문 또는 패키지 배포물 확인을 직접 요구하고, 인접 버전을 증거로 삼지 않도록 명확히 했습니다. Luna 세션에서는 설치·픽스처 수정·테스트 실행이 없었습니다.
- **최종 fallback 재시도:** 명확해진 문구를 전역 적용한 뒤 같은 픽스처를 새 Luna Medium 세션에서 재실행했습니다. Context7 resolve/query 후 정확한 `v1.0.0` GitHub 태그와 npm/unpkg 패키지 배포물을 웹 조회 도구로 열려고 했으나 캐시/요청 제한 또는 내부 오류가 발생했습니다. 세션은 정확 호환이 미검증이라고 밝혔고 설치·수정·테스트 실행은 하지 않았습니다. **부분 통과:** 이전과 달리 정확 원문 fallback을 시도했고 현재 v1 문서를 정확 버전의 증거로 취급하지 않았지만, 해당 세션에서는 원문을 얻지 못했습니다. 다만 현재 소스 문서만으로 “호환 가능성이 높다”고 시작한 추정은 정확 버전 근거가 뒷받침하지 않습니다. 권장 답변은 공식 원문을 확보하기 전까지 정확 버전은 미검증이라고만 말하는 것입니다. 규칙은 더 수정하지 않고 시나리오도 추가하지 않았습니다.

# 검증 기록 요약

[English 원문](validation.md) | **한국어**

이 문서는 상세 검증 기록의 한국어 요약입니다. 정확한 실행 환경, 시나리오 표, 관찰 내용과 토큰 수는 [영문 원문](validation.md)을 기준으로 확인하세요.


## 영문 상세 기록

- **166차 (2026-11-26):** 요청한 세 조합군(OpenSpec+Superpowers, OpenSpec+전문 스킬 또는 단독, Superpowers+전문 스킬 또는 단독)을 검증했습니다. 승인된 OpenSpec 구현에는 `using-superpowers`와 TDD 절차가 맞았고, 승인 대기 OpenSpec의 독립 오타 수정에는 추가 스킬이 필요하지 않았습니다. 반면 OAuth 코드를 보안 리뷰로 요청했을 때 보안 스킬만 선택하고 코드 리뷰 절차를 빠뜨리는 문제가 두 번의 규칙 문구 조정 끝에 드러났습니다. 규칙을 “보안·UX 등 도메인 리뷰로 표현해도 소스 코드 리뷰이면 `requesting-code-review`를 호출하고, 별도 분석에 필요한 도메인 전문가를 추가”하도록 구체화했습니다. 마지막 재실행은 두 스킬을 모두 읽고 요구사항·코드·테스트 범위를 대조했습니다. Superpowers+보안 사례는 디버깅/TDD/보안/코드 리뷰를 역할별로 사용했고, 단순 헬퍼 수정은 Superpowers 게이트와 TDD만 사용했습니다. Setup 테스트 45/45 통과. 세션 토큰은 전체 대화 문맥 포함값이며 스킬별 비용으로 볼 수 없습니다. 자세한 내용은 [166차 기록](validation-policy-batch-166.md)을 참조하세요.

- **167차 (2026-11-26):** 새 공개 API의 계정 범위 커서 페이지네이션을 구현하며 OpenSpec+Superpowers+API 설계+보안+코드 리뷰 조합을 검증했습니다. TDD는 구현 전 실패와 구현 후 4/4 통과를 확인했고, HTTP 라우트와 실제 저장소 연결은 없는 한계로 보고했습니다. 리뷰에서 구분자가 맞지만 timestamp가 잘못된 커서가 통과하는 입력 경계 누락이 발견됐습니다. 구조화 입력은 모양이 틀린 값뿐 아니라 형태는 맞지만 필드 값이 잘못된 경우와 부작용 전 거부도 확인하도록 일반 규칙을 추가했습니다. 최신 규칙으로 재실행한 버그 수정은 디버깅/TDD/보안/코드 리뷰만 사용하고 Superpowers/API 설계 스킬을 반복 호출하지 않았으며 6/6 통과했습니다. 전체 두 실행 입력 1,501,400(캐시 1,381,760), 출력 12,217, 추론 6,111 토큰입니다. 자세한 근거는 [167차 기록](validation-policy-batch-167.md)을 참조하세요.

- **168차 (2026-11-26):** React 컴포넌트 리뷰에서 OpenSpec+Superpowers 게이트+코드 리뷰+Vercel React 지침을 사용했습니다. 테스트 2/2는 순수 필터 함수만 검증해 검색어 양끝 공백 결함은 놓쳤고, 입력/Clear 이벤트는 미검증이라고 구분했습니다. Vercel React 지침을 읽고도 최종 스킬 목록에서 누락한 점은 보고 규칙에 반영하고 재실행으로 바로잡았습니다. CI 카나리 리뷰는 처음 두 번 OIDC 배포 권한이 있는데 보안 스킬을 놓쳤습니다. “기존 신뢰 경계 리뷰에도 보안 전문 스킬 적용”을 명시한 뒤 CI·롤아웃·코드 리뷰·보안 역할을 모두 읽었습니다. checkout v4.2.2는 Context7과 공식 정확 버전 자료로 확인했습니다. 기존 테스트가 없어 실행하지 않았고, 실제 GitHub 배포/롤백은 검증하지 않았습니다. 최종 규칙에서 Setup 48/48 통과. 네 실행 총 입력 1,196,906(캐시 1,024,640), 출력 11,350, 추론 3,484 토큰입니다. 세부 근거: [168차 기록](validation-policy-batch-168.md).

- **169차 (2026-11-26):** 미결 OpenSpec 결정과 명시적 Superpowers/TDD 요청이 충돌할 때 구현·테스트·관련 스킬을 보류하고 독립 README 오타만 고치는 경로를 확인했습니다. 순차 Product→조건부 Legal 승인 시나리오에서는 첫 두 실행이 후속 승인까지 요청했습니다. 규칙을 보완한 최신 재실행은 첫 Product 결정만 직접 요청하고 후속 승인은 답변 뒤 재평가했습니다. Context7이 없는 격리 실행에서는 checkout v4.2.2의 공식 정확 태그 자료로 대체해 자격 증명 지속 설정을 확인했고, 실제 GitHub 실행은 미검증으로 남겼습니다. Setup 48/48 통과. 여섯 실행 입력 1,085,978(캐시 924,928), 출력 6,921, 추론 1,521 토큰입니다. 세부 근거: [169차 기록](validation-policy-batch-169.md).

- **170차 (2026-11-26):** 테넌트 간 프로필 캐시 누출 결함을 구현 중심으로 검증했습니다. 에이전트는 `systematic-debugging`, 보안, TDD, 코드 리뷰를 각각 원인 추적·테넌트 경계·회귀 증거·최종 diff 검토에 사용했습니다. Superpowers는 선택하지 않았고, Ponytail/API 설계/완료 검증도 추가하지 않았습니다. 교차 테넌트 캐시 적중 테스트가 수정 전 실패하고 수정 후 전체 픽스처 3/3 통과했습니다. 실제 저장소·동시성은 미검증입니다. 규칙에서 새 누락은 없어 수정하지 않았습니다. 입력 429,367(캐시 376,704), 출력 1,897, 추론 291 토큰입니다. 자세한 내용은 [170차 기록](validation-policy-batch-170.md)을 참조하세요.

## 현재 결론

전체 에이전트 품질 벤치마크와 새 물리 컴퓨터의 설치 통합 검증은 아직 수행하지 않았습니다. 다만 163차에서 깨끗한 임시 Codex 홈에 실제 설치하고 doctor 검사를 통과했습니다. 제한된 런타임 검증은 모든 환경의 품질 동등성이나 토큰 절감 효과를 입증하지 않습니다. 호스트·모델·세션 문맥이 포함된 토큰 수는 Grounded에만 귀속할 수 없습니다.

[165차 상세 기록](validation-policy-batch-165.md)

[163차 상세 기록](validation-policy-batch-163.md)

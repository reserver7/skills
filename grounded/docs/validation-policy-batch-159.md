Regression assertions identified four general wording gaps over this batch: explicit requested surfaces must retain their owner skill before files/dependencies exist; auth/authz and tenant-boundary changes require review regardless of patch size; default listings can hide ignored OpenSpec files, so absence must be checked with ignore-aware search or known-path probes; and agents must read matched skill files directly instead of listing skill catalogs. The final policy now states these rules without adding scenario-specific skill bundles. Security analysis and diff review remain separate responsibilities.

The focused policy tests passed **16/16** after the latest wording update. The full setup suite passed **40/40**; Python compilation, validation-runner `--help`, policy size/hash, local-link checks, and repository `git diff --check` also passed for the final fingerprint. External skill bodies were copied unchanged into disposable fixtures and were not edited in the repository. No production project, database, release, or Git history was changed.

The finite cohort covers React, auth, CI/rollout, ignored-spec discovery, and narrow code fixes; it does not prove parity across all hosts or every skill.

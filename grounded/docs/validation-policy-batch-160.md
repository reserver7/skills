### Policy changes carried forward

- Existing work now has a skill-free preflight gate: inspect active OpenSpec decisions/specs/tasks, including ignored files, and target code/config/dependencies/tests before selecting or reading skills. Keep those command steps separate.
- At one code revision, use one test command for identical coverage. Choose the focused or project command based on the acceptance needs; run both only when each adds required coverage.
- Treat public API/module-contract behavior changes as nontrivial for TDD, regardless of patch size.
- Use `doc-updater` for coordinated cross-document or contract updates, even when each edit is short. Direct editing remains available for short factual changes confined to one document.
